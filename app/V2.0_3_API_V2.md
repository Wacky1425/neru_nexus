# V2.0-3 API v2

## Contract

API v1 remains supported:
- request field: `action`
- version: `apiVersion=1`

API v2 canonical request:
- request field: `route`
- version: `apiVersion=2`

Successful/error envelopes include:
- `apiVersion`: version negotiated for this client
- `serverVersion`: current server version
- `requestId`: request correlation ID
- `success`
- `status`
- `data` or `error`

This lets an old v1 Flutter build continue talking to the same GAS deployment while the new Flutter build moves to v2.

## Important deployment order

1. Deploy GAS first.
2. Run `runReleaseChecks()`.
3. Only after GAS passes, replace Flutter with the V2.0-3 build.
4. Run `flutter test`.
5. Run `flutter analyze`.
6. Open Home and the transaction list once against the live API.

There is no spreadsheet migration in V2.0-3.

## Public manual GAS function

The only function required for the normal final check is:

`runReleaseChecks()`

Optional diagnostic:

`verifyV203ApiV2()`

Both intentionally have no trailing underscore.
