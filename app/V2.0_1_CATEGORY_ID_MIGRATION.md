# V2.0-1 Category ID Migration

Goal:
Move transaction/category relationships toward stable IDs without breaking V1 screens.

Live migration:
1. Deploy GAS.
2. Run `migrateV201CategoryIds_()`.
3. Confirm `verification.ready == true`.
4. Run `runReleaseChecks()`.

Changes:
- `T_Transactions` gains `major_category_id` and `sub_category_id` at the end.
- Existing `major_category` and `sub_category` remain.
- Existing rows are backfilled from `M_Categories`.
- New/imported/edited transactions dual-write names and IDs.
- Flutter sends category IDs selected from Master and reads IDs from transaction APIs.
- Backend rejects mismatched ID/name pairs.
- `verifyV201CategoryIds_()` detects missing/unresolved/mismatched rows.

Rollback safety:
The migration does not delete or rename existing columns. V1 name-based code remains functional.
