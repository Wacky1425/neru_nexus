# V2.0-2 Account ID Migration

## Purpose
Move transaction/account relationships to stable IDs without deleting the existing account-name fields.

## Live migration order
1. Deploy the GAS V2.0-2 build.
2. Run `migrateV202AccountIds()`.
3. Confirm:
   - `verification.ready == true`
   - `unresolvedReferenceCount == 0`
   - `mismatchCount == 0`
4. Run `runReleaseChecks()`.
5. Replace Flutter with the V2.0-2 build.
6. Run `flutter test` and `flutter analyze`.

## Schema changes
`T_Transactions` gains three columns at the end:
- `account_id`
- `from_account_id`
- `to_account_id`

Existing columns remain:
- `account_name`
- `from_account`
- `to_account`

## Safety
- Migration is idempotent.
- No existing account-name column is deleted or renamed.
- Existing rows are backfilled from `M_Accounts`.
- Aliases are resolved before ID assignment.
- Inactive historical accounts can still resolve.
- Duplicate IDs or canonical names in `M_Accounts` cause a clear error.
- New writes reject unresolved account references rather than storing broken ID relationships.

## Public GAS entry points
These are intentionally public and do not end with `_`:
- `migrateV202AccountIds()`
- `verifyV202AccountIds()`
- `runReleaseChecks()`
